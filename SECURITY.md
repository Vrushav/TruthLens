# Security Policy

## Supported Versions

The latest stable release of TruthLens receives security updates and bug fixes.

| Version | Supported |
|----------|-----------|
| 1.x | ✅ Yes |
| < 1.0 | ❌ No |

---

## Reporting a Vulnerability

If you discover a security vulnerability in TruthLens, please report it responsibly.

Please include:

- A clear description of the vulnerability
- Steps to reproduce the issue
- Expected behavior
- Actual behavior
- A proof of concept (if available)
- Your operating system and Python version

Please do **not** publicly disclose security vulnerabilities until they have been reviewed.

---

## Response Process

When a valid security report is received, the maintainer will:

1. Acknowledge receipt of the report.
2. Investigate the issue.
3. Develop and test a fix.
4. Release a patched version if necessary.
5. Credit the reporter when appropriate.

---

## Scope

TruthLens focuses on:

- Static Python code analysis
- AI-generated code trust evaluation
- Security vulnerability detection
- Trust score generation
- HTML and JSON reporting

Issues outside these areas may be considered out of scope.

---

## Best Practices

Users should:

- Keep TruthLens updated to the latest release.
- Review analysis results manually before making security decisions.
- Avoid relying solely on automated analysis for high-risk production environments.

TruthLens is designed to assist developers, not replace professional security reviews.

---

## Contact

For security-related concerns, please open a private GitHub security advisory or contact the project maintainer through GitHub.
